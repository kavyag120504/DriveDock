# DriveDock Demo Seed Toolkit

## What this is

A reproducible, idempotent script that populates a development MongoDB database with
realistic demo data. **Never point this at a production database.**

---

## What is real vs. synthetic

| Data | Source | Nature |
|---|---|---|
| Service-provider locations (names + coordinates) | OpenStreetMap | **Real public place data** — see attribution below |
| Regional vehicle-registration counts (per RTO) | VAHAN open data via India Data Portal | **Real aggregate statistics** |
| All people (names, emails, phones, passwords) | Generated by this script | **Entirely fictional** |
| All vehicles (reg numbers, makes, models) | Generated by this script | **Entirely fictional** — uses unissued "ZZ" series |
| All documents (certificates, dates) | Generated by this script | **Entirely fictional** — marked SAMPLE NOT A REAL DOCUMENT |
| Compliance percentages (50% valid / 15% expiring / etc.) | Hard-coded in seed script | **Simulated** — no open-source compliance-rate data exists |
| Bookings, violations, challans, payments | Generated by this script | **Entirely fictional** |

### Important notice about providers

The petrol pumps imported from OpenStreetMap are **real businesses at real locations**.
They have **not joined DriveDock** and must **not** be presented as partners or endorsers
of DriveDock in any context. They appear only so that the map UI shows realistic pin locations.

## Configuration

Set these environment variables (or accept the defaults shown):

| Variable | Default | Purpose |
|---|---|---|
| `SEED_STATE` | `Maharashtra` | Indian state to use for RTO mapping and VAHAN filter |
| `SEED_AREA_NAME` | `Mumbai` | Overpass area name for petrol-pump lookup |
| `SEED_PROVIDER_COUNT` | `30` | Max OSM providers to import |
| `SEED_VEHICLE_COUNT` | `80` | Total synthetic vehicles to create |
| `SEED_DEMO_PASSWORD` | `Demo@12345` | Shared password for all demo accounts |
| `SEED_RANDOM` | `42` | Seed for the deterministic PRNG (same seed = same data) |

## NPM scripts

```bash
npm run seed            # idempotent: clears previous run then seeds fresh
npm run seed -- --dry-run  # prints counts, writes nothing
npm run seed:clear      # removes ONLY seed data tracked in seedRegistry
npm run seed:report     # prints current counts, logins, breakdowns
```

## Optional data files (place in `server/scripts/seed/data/`)

| File | How to obtain | Effect |
|---|---|---|
| `puc_centres_manual.csv` | Compile by hand; columns: `name,lat,lng,address` | Extra PUC centres imported as approved providers |
| `vahan_registrations.csv` | Download from [data.gov.in VAHAN dataset](https://vahan.parivahan.gov.in/vahan4dashboard/) | Proportional vehicle distribution per RTO; populates `regionBaselines` collection |
| `osm_fuel.json` | Auto-created on first run (Overpass cache) | Prevents repeated Overpass requests |

### VAHAN CSV notes

The seed auto-detects column names from the header row. If a required column cannot be
found, the script stops and prints the detected headers. Required columns: state, RTO/district,
registrations/count. Optional: fuel type, vehicle class, date/year.

---

## How the seedRegistry protects existing data

Every document inserted by this script is recorded in the `SeedRegistry` MongoDB collection
with its `_id`, collection name, and run ID. `seed:clear` deletes **only** those specific
document IDs — it never runs a broad `deleteMany({})` on any existing collection.

## Generating fresh data for a different city

```bash
SEED_STATE="Karnataka" SEED_AREA_NAME="Bengaluru" SEED_PROVIDER_COUNT=25 npm run seed
```
